# Afterlife

SC4SIM runs the Afterlife engine of the NEON-derived pack (Winners in Heaven, Sinners in Hell, Hell's native
population, I.M.P. clients and kills, redemptions) and, since 1.9.1, puts its headlines in the news ticker.
The statistics are **fictitious and cosmetic**: Sims never die in the real simulation. The module only **reads**
`game.g_health_coverage_p`, `game.g_city_r_population`, `game.ga_crime`, `game.ga_education`, `game.ga_life_exp`
and, since 1.9.3, the age, population, EQ and life expectancy of the residential simulator's tracts. It changes
nothing in the game and patches no game code.

**The DLL is now the only implementation.** `AFTERLIFE.lua` and `PACK_CONSTANTS.lua` are no longer part of the pack:
the calculation, the constants and the news roster are all in SC4SIM.dll. Without the DLL, or with
`[Afterlife] Enabled=false`, there are no Afterlife statistics and no Afterlife news.

## Files in the pack

| File | Content |
| --- | --- |
| `SC4SIM.dll` | The calculation, the constants and the news roster (62 characters, 8 events). |
| `CAM_LUA_Controller.dat` | Lua `CA63E2A3-4A5E8EF6-8BB3C100` = `lua/afterlife_news.lua`, the news script. |
| `CAM_Afterlife_News_en.dat` | 62 LTEXT (`2026960B`, group `6A231EA4`, instances `BB3C1000`-`BB3C1065`): the English ticker lines; 18 LTEXT (group `EA5524EB`, `BB3C3000`-`BB3C3011`): labels and values of the query rows. |
| `Cemetery_and_Church.dat` | The church and cemetery query UIs with the Afterlife rows. |

Both `.dat` files are generated by `tools/afterlife-news/build_news.py` (see [Building the news](#building-the-news)).

> **LTEXT group.** The advisor looks up `text@XXXXXXXX` in the LTEXT group `0x6A231EA4`: all 424 `text@` strings of
> the game's and CAM's Lua resolve there. The first build used `0x6A231EAA` (the group of the game's UI strings), and
> the ticker showed `***_NOT_IN_TEXT_DATABASE_*** text@BB3C...`.

## Lua functions

When a city opens, the DLL registers two global functions in the city's advisor Lua:

| Function | Meaning |
| --- | --- |
| `run_afterlife_balance_variables(ret_type)` | The current values (since 1.9.3 the DLL runs the cycle itself, see [Mortality](#mortality-and-generation-resets-193)). `ret_type` is `D`, `W`, `S`, `C`, `K`, `R`, `H`, `P`, `T`, `N` or `A` (total deaths, Winners, Sinners, I.M.P. clients, I.M.P. kills, redeemed, Hell, Heaven, total I.M.P. kills, Hell natives, Heaven natives); another value returns nothing. |
| `get_news_ticker_character(event_type)` | A random character on topic for the event: a table with `full_name`, `role`, `source`, `species` and `ticker_text_id`. |

After each cycle, and when a city opens, the DLL copies all 34 fields into the Lua table `afterlife_grid_var`. `SC4SIM.log` says which
functions were registered.

## News

`afterlife_news.lua` defines one fluff-news advice per character, whose title is that character's ticker line. Once
per game month the first trigger evaluated runs `afterlife_news.update()`:

1. `run_afterlife_balance_variables` reads this month's values;
2. with a chance of `NEWS_CHANCE` (50%), an event is chosen among those this month's numbers support, rotating
   month by month;
3. `get_news_ticker_character` picks a character for it, and only that character's advice triggers.

| Event | Condition | Characters |
| --- | --- | --- |
| `NATURAL_DEATH_REPORT` | natural deaths > 0 | Katie Killjoy, Tom Trench |
| `PREMATURE_DEATH_REPORT` | premature deaths > 0 (1.9.3) | 670 News Health Desk, Hell's Intake Clerk (original desk characters of the mod) |
| `IMP_KILL_REPORT` | I.M.P. kills > 0 | Blitzo, Moxxie, Millie, Striker |
| `REDEMPTION_REPORT` | redeemed > 0 | Charlie, Vaggie and the hotel (10) |
| `HEAVEN_REPORT` | new Winners > 0 | Adam, Lute, Abel, Sera, Emily, St. Peter, The Speaker of God |
| `OVERLORD_REPORT` | Hell not empty | the Overlords and their circle (13) |
| `SEVEN_DEADLY_SINS_REPORT` | Hell not empty | Lucifer, Lilith and the six Sins |
| `HELL_NATIVE_REPORT` | Hell natives beyond the fixed 9 | Stolas, Loona, Verosika and the Hellborn (16) |

The same character comes back at most once a year (`FREQUENCY_DAYS`); each headline stays 30 days. Without the DLL
every trigger is false. The ticker lines are original text written for the mod.

If a Lua script defines `news_ticker_event_characters` and `hell_news_characters`, `get_news_ticker_character` uses
them instead of the built-in roster.

## Church and cemetery queries

Both query UIs keep the game's own row and get new ones under it; the window grows and the Close button moves down.

| Query | Rows |
| --- | --- |
| Church (`00000000-96A006B0-CA8B9AA2`) | Winners This Month, Souls in Heaven, Sinners Redeemed, Heavenborn Population |
| Cemetery (`00000000-96A006B0-CA8B96C2`) | Deaths This Month, I.M.P. Victims This Month, Sinners This Month, Souls in Hell, Hellborn Population |

Each row has a label LTEXT and a value LTEXT whose text is a `#afterlife_grid_var.FIELD#` token, the same kind of
`#game.g_...#` token that query texts expand when they are shown. `afterlife_news.lua` sets every field shown to 0
when it loads, so the rows show 0 until the first monthly cycle. Rows and labels are in `UI_ROWS` of
`build_news.py`; `--ui` applies them to `Cemetery_and_Church.dat` (it refuses a file that already has them).

> **To check in game:** that query texts expand a token of a Lua table other than `game`. If a row shows the raw
> token, the values have to be exposed differently (for example as `game` fields set by the DLL).

## Mortality and generation resets (1.9.3)

The DLL runs one cycle on the game's new-month message, the message that also starts the residential simulator's
monthly cycle (before 1.9.3 the cycle ran when the news script first asked for it).

- **Base deaths.** The game's life expectancy (`game.ga_life_exp`, years) sets them: each generation is replaced about
  once per life expectancy, so `residents x LIFE_EXPECTANCY_DEATH_SCALE / (12 x life expectancy)` die each month.
  Life expectancy follows the residents' health (hospitals, pollution), so an unhealthy city has more deaths. If the
  game gives 0, the old per-capita rate (`BASE_MORTALITY_RATE_PER_CAPITA`, worsened by low health coverage) is used.
- **Generation resets.** The residential simulator keeps one average age per tract. When it passes the tract's life
  expectancy, the game sets it back to the reset age (40) and cuts EQ and HQ: the closest thing to "a generation
  died". Every month the DLL reads the age grid and the three population grids and keeps last month's ages: a populated
  tract that is now at the reset age and was not last month was reset. `WAVE_DEATH_SHARE` (5%) of its residents
  count as deaths, up to `MAX_WAVE_DEATH_FRACTION_POP` (1% of the residents) a month.
- **Causes.** A reset where the tract's life expectancy is at or above the reset age is old age (natural deaths). A
  tract whose life expectancy is below the reset age (health under 40 with the default curve) is reset on every
  monthly visit: it counts as **premature deaths** (illness, pollution), at most once every
  `CHRONIC_RESET_INTERVAL_MONTHS` (12) months per tract, and the news can report it (`PREMATURE_DEATH_REPORT`).
- **Judgment by wealth.** Base deaths and I.M.P. victims are judged with the city's EQ. Wave deaths are judged with the
  EQ of their own wealth level in that tract; premature deaths add `PREMATURE_SIN_BONUS` (0.1) to the Sinner share.
- **Catches.** A tract that empties drops to age 0 and newcomers lower the age: neither counts. A tract whose age lands
  on 40 by mixing with newcomers can be miscounted once. In very large cities a residential cycle can overrun a month;
  the reset is then seen the next month.

`SC4SIM.log` writes a line for every month with resets. New fields of `afterlife_grid_var`: `LIFE_EXPECTANCY`,
`BASE_DEATHS`, `WAVE_DEATHS`, `PREMATURE_DEATHS` (`NATURAL_DEATHS` = base deaths + old-age wave deaths;
`TOTAL_DEATHS_THIS_CYCLE` also counts premature deaths and I.M.P. victims).

## Deathcare (1.9.4)

Cemeteries and crematoria collect the dead of each month by radius and capacity; uncollected dead lower the health
of their tract. See [deathcare.md](deathcare.md).

## Saved with the city (1.9.3)

The game saves nothing about deaths. When it saves a city, the DLL writes the cumulative populations
(`WINNER_POPULATION_HEAVEN`, `SINNER_POPULATION_HELL`, `REDEEMED_TOTAL`, `IMP_KILLS_TOTAL`) to `SC4SIM_Afterlife.ini`,
next to the DLL, in a section named after the city's serial number (`City.XXXXXXXX`); when the city opens they are
read back and the native populations recomputed. A city closed without saving reopens with the values of its last
save. `SAVE_WITH_CITY=0` turns this off.

## Constants

The balance constants live in the DLL (`Afterlife::Constants` in `src/afterlife/AfterlifeModel.h`); their defaults
started as the AFTERLIFE values of the former `PACK_CONSTANTS.lua` and since 1.9.2 differ where noted (the test fixture
follows the DLL, not the pack's original file). Each one can be overridden in the `[Afterlife]` section
of `SC4SIM.ini` (a commented line keeps the default):

| Group | Keys and defaults |
| --- | --- |
| Mortality | `LIFE_EXPECTANCY_DEATH_SCALE` 1.0 (1.9.3); without a life expectancy: `BASE_MORTALITY_RATE_PER_CAPITA` 0.0006, `HEALTH_COVERAGE_WEIGHT` 1.5 |
| Generation resets (1.9.3) | `WAVE_DEATH_SHARE` 0.05, `MAX_WAVE_DEATH_FRACTION_POP` 0.01, `PREMATURE_SIN_BONUS` 0.1; DLL settings `DEATH_WAVES` 1, `TRACT_RESET_AGE` 40, `CHRONIC_RESET_INTERVAL_MONTHS` 12, `SAVE_WITH_CITY` 1 |
| Judgment | `EDUCATION_REFERENCE` 100 (1.9.3; was 500), `BASE_SIN_RATIO` 0.5, `CRIME_WEIGHT` 0.3, `EDUCATION_WEIGHT` 0.3, `SIN_RATIO_MIN` 0.1, `SIN_RATIO_MAX` 0.9 |
| I.M.P. | `IMP_CLIENT_RATIO` 0.002, `IMP_SUCCESS_CHANCE` 0.15, `IMP_KILL_RANDOM_VARIANCE` 2, `MAX_IMP_KILL_FRACTION_POP` 0.01 |
| Redemption | `REDEMPTION_RATIO` 0.0015 |
| Hell's natives (per Sinner) | `HELL_IMP_RATIO` 1.0, `HELL_HELLHOUND_RATIO` 0.6, `HELL_SUCCUBUS_RATIO` 0.4, `HELL_INFESTOR_RATIO` 0.16, `HELL_POSSESSOR_RATIO` 0.1, `HELL_BAPHOMET_RATIO` 0.02, `HELL_REAPER_RATIO` 0.01, `HELL_GOETIA_ARS_GOETIA_RATIO` 0.001 (1.9.2: 20 times the PACK_CONSTANTS values) |
| Hell's fixed population | `FALLEN_ANGELS` 2, `SEVEN_DEADLY_SINS` 7 |
| Heaven's natives (per Winner, 1.9.2) | `HEAVEN_ANGEL_RATIO` 1.0, `HEAVEN_CHERUB_RATIO` 0.6, `HEAVEN_EXORCIST_RATIO` 0.3, `HEAVEN_SERAPHIM_RATIO` 0.01 |
| Heaven's fixed population | `SERAPHIM_COUNCIL` 3 (Sera, Emily, the Speaker of God) |

Both native populations always outnumber the souls they live with: Hellborn > Souls in Hell, Heavenborn > Souls in
Heaven. If `SC4SIM.ini` lowers the ratios too far, the DLL adds Imps (Hell) or Angels (Heaven) to keep it so.

`game.ga_education` is the city's EQ, on a 0-200 scale. The old `EDUCATION_REFERENCE` of 500 (marked *TUNE THIS*) was
above the whole scale, so education always pushed toward Sinner; since 1.9.3 it is 100, the middle of the scale.
`TRACT_RESET_AGE` must match the reset age of the residential tuning exemplar (property `0xCA027307`, default 40).
A value that is not a number is ignored with a warning in `SC4SIM.log`; `EDUCATION_REFERENCE=0` is changed to 1.
If one of the four `game` inputs is missing, `run_afterlife_balance_variables` returns nothing, changes no state, and
`SC4SIM.log` lists the missing names once per city.

## Behaviour

- **Random numbers** come from a generator seeded once from the operating system's entropy (the old Lua used
  `game.g_population`). Only the I.M.P. kill jitter and the ticker pick are random.
- **Cumulative values** (`WINNER_POPULATION_HEAVEN`, `SINNER_POPULATION_HELL`, `REDEEMED_TOTAL`, `IMP_KILLS_TOTAL`)
  are kept by the DLL and saved in `SC4SIM_Afterlife.ini` when the city is saved (see [Saved with the city](#saved-with-the-city-193)).
- A fractional `IMP_KILL_RANDOM_VARIANCE` is truncated to an integer, as `math.random` does in Lua 5.0; a negative one
  is treated as 0.

## Building the news

`tools/afterlife-news/roster.py` is the single source of the characters, the event lists and the ticker lines.
`build_news.py` regenerates from it the built-in roster of `AfterlifeModel.cpp`, `lua/afterlife_news.lua`, the test
fixture and, with `--dat`, the two `.dat` files:

```sh
python3 tools/afterlife-news/build_news.py --dat path/to/CAM_LUA_Controller.dat out/CAM_LUA_Controller.dat out/CAM_Afterlife_News_en.dat
```

The other entries of `CAM_LUA_Controller.dat` are copied unchanged (written uncompressed); the news script replaces
any earlier copy with the same instance. Rebuild the DLL after changing the roster.

## Tested

`src/afterlife/AfterlifeModel.cpp` has no game or Windows dependency. `tools/afterlife-test` compares it with the last
Lua version of the engine, kept as a test fixture in `tools/afterlife-test/reference/` (not shipped):

- 12,000 cycles with random constants, life expectancies and generation resets: all 34 state values matched;
- the 32 DLL defaults are equal to the constants of `PACK_CONSTANTS.lua`;
- the built-in roster is equal to the fixture's tables, and the ticker pick returns the same character for every event
  type and index;
- 40,000 cycles with the real constants: all 34 state values matched.

The fixture follows the DLL's model: since 1.9.2 and 1.9.3 its natives, mortality and generation resets are kept in
step with `AfterlifeModel.cpp`. The reading of the residential simulator's grids (`Afterlife.cpp`) is checked against
the 1.1.641 executable (vtable slots 25, 29, 37, 41) but not yet in game.

`afterlife_news.lua` was run in a Lua interpreter with stub game functions (one cycle per month, one trigger true per
month). The Lua bridge (`Afterlife.cpp`), the news script and the LTEXT are **not yet tested in game**: check
`SC4SIM.log` after opening a city, then watch the ticker for a few months.

The four `game` variable names the module reads were also checked in the 1.1.641 executable: all of them exist.
